Test build of Bobix 0.2.0. This is a pre-release; the newest stable version is still v0.1.3.

## What's new

**Work: any repo, GitHub and GitLab alike**
- **Pick the repos to list.** Work → Repos to list shows every repo your `gh` / `glab` can reach, grouped by host, with search and Select all / none. The first time, Bobix ticks the ones active in the last 90 days, and it remembers your ticks.
- **One issue list** across the ticked repos, newest first, 20 a page, with an **All / Mine / Unassigned** filter. Issues nobody is assigned to show too.
- **Where is this repo's code?** Start asks once per repo when Bobix doesn't know the folder: **Choose folder…** (the folder's git remote is checked) or **Clone…**. Bobix also finds clones by itself by reading only the `.git/config` remotes in common folders. Remembered folders are listed in Settings → Work, each with Forget.
- **Fix it in another project.** An issue can live in one repo while its code is in another. Start lets you pick the code's project, and the MR/PR closes the issue across repos.
- **GitHub ticket flow**, the same as GitLab's: plan gate, checks, review, Open PR, and CI.

**Ticket flow: checks before done**
- Before a ticket is done, the session runs the project's tests, build and lint and pastes the results. Work shows ✓ checks / ⚠ no checks and ✓ reviewed.
- **Review in Claude** opens a second session that reviews the branch against its plan.
- **Open MR / Open PR…** from a done ticket. You can edit the title and description, and nothing is sent until you click. **Clean up** warns about commits that aren't pushed.
- **CI status** on the ticket's MR/PR. When CI is red, **Copy Fix CI** gives a prompt to paste, and Overview flags it.
- **CLAUDE.md check.** The Start box and Skills say when a project has no test command, and offer **Add Tests line** or **Copy /init**.

## What's fixed
- **"glab is not signed in to any GitLab" while it was.** A host in glab's config with no token (such as gitlab.com) made the whole check time out. Each host is now checked on its own, with a 10 s limit, and a failing host is named and skipped.
- **From the final check before this build:**
  - The Stand-up, Today's report and Start dialogs fit again, and closed dialogs no longer show under the panel.
  - "Add a Tests line…" opens the project's CLAUDE.md item.
  - Settings → Work opens at the top.
  - The Clean up warning and the Open MR form scroll into view.
  - Page 2 says "Reading your issues…" until it's full.
  - ✓ checks / ✓ reviewed stay on the row after an MR exists.
  - The model split reads "explore with Haiku · edit with Sonnet · review with Opus".
  - Repo search hides empty groups.

## Known gaps

- Builds are not code-signed: macOS and Windows warn on first launch.
- Checked by eye on macOS only. Windows and Linux are covered by the CI smoke run, not by hand.
- **Room needs a tailnet where laptops can reach each other.** Company tailnets that only allow user → server don't work yet. The tab stays visible, and a new design is pending.
- The native folder dialogs (Choose folder…, Clone…) and "Start in Claude" were not clicked in the automated check.
- The ticket flow was not run inside the Claude desktop app.
- The skills audit does not edit plugin settings. The first audit after start reads 30 days of transcripts and can take several seconds.
- The hourly usage chart from the design is left out; Overview shows the live sessions' token split instead.
- Picture pets (a pet drawn from your own picture) are hidden in this build.
