# Roadmap and open work

What Bobix still lacks, what is done but not released, and what nobody has verified yet. Update this file when an item lands, ships or changes. Last updated: 2026-11-04 (v0.1.3).

**Product direction (v3):** [product-direction.md](product-direction.md) records where Bobix goes next as a personal assistant for working well with Claude Code, in five build steps: measure usage, skills audit and model routing, a GitLab ticket flow, habits into skills, and a war room with its security ([#110](https://github.com/baonguyen-agilityio/bobix/issues/110)).

## 1. Done on `main`, not released yet

- **A tidier panel, and skills in a tab of their own** ([#92](https://github.com/baonguyen-agilityio/bobix/issues/92), on `develop` after 0.2.0-rc.3): tabs are Board · Skills · Settings · Setup. The Board drops the four count tiles, the subtitle under the date, the "Not seen on this machine" pill on each project (said once above those projects), "Found by Bobix" and a Stuck work card with nothing stuck today (older quiet items stay one line), and says the connection only when it is lost; an empty In progress / Waiting for review / Done today is one line. A narrow window shows the sections one under another. The pets guide lives in Setup only, with the tour's replay next to it. The **Skills** tab holds your role, your skills (pin, roles, where each comes from) and, per project, its project and team skills, its process file with the skills it names that Claude lacks (and the line to copy), and the skill picked for its folder (habits), with Forget; these rows left Settings › Work. Same settings keys, nothing migrated. A session on an issue that is not assigned to you (the board reads only yours) no longer lands in "Sessions without a ticket": Bobix reads that one issue and shows the session under it. Checked in the real app on macOS with made-up data; not on Windows / Linux.
- **A pet leaves when its Claude is gone**: a session whose claude process ended without saying so (its terminal closed, a crash, a kill) is removed within about 5 s instead of staying on screen, waiting, until Bobix restarts. Only a process seen running as `claude` (or `node`) counts, so a shell between Claude and the hook never makes a live session look gone. Checked on macOS; Windows and Linux not yet.
- **Pets stay on top on Linux**: the pets window lost "always on top" once it had been hidden and shown again (seen on Ubuntu, Wayland through XWayland, v0.1.3: `alwaysOnTop: false` in Copy diagnostics). It is set again each time the window shows, and CI now fails if it isn't on top.
- **Pets take the mouse on Linux Wayland**: through XWayland, a pet could be hovered, clicked or dragged only while an X11 window (such as the panel) was under it. The pets overlay now has a window shape around the pets, so the X server hands them the mouse directly.
- **Linux dock**: the `.deb` sets `desktopName`, so its `.desktop` entry has `StartupWMClass=bobix`, the windows' real class (it said `Bobix`).
- **Panel on wide screens**: the details pane grows with the window (400 to 640 px) and the page may be 1,920 px wide instead of 1,440, so a full-screen panel leaves less empty space at the sides; scrollbars are thinner (10 px) and have no arrows.
- **Panel layout fixes**: a session row's title, level, folder and labels wrap instead of overlapping the status column or shrinking to nothing; rows collapse by the list's width, not the window's (the title shrank to 0 px at 981–1,100 px with details open); the panel shows once its labels and first sessions are in, so the top bar no longer jumps on open, and when it wraps the connection status stays on the right; sessions that arrive before the settings no longer throw (the board was drawn in part until the settings came); a hovered pet's card sits above other pets' bubbles.
- **Panel**: the final report shows the answer's Markdown (lists, tables, code) and keeps up to 32,000 characters instead of 600 on one line, and folds away with a click; status pills sit in the middle of their row; the log puts the time on one line, marks each kind of event, folds repeats ("×3") and shortens long commands in the middle (whole on hover); details never scroll sideways; text of the same kind has one size (the session's title in its details had lost its size to the Setup cards' heading rule).
- **Open session**: a CLI in the Claude app's own terminal brings the Claude app forward, also on Wayland, and is named "Claude" (it was "claude-desktop" and could not be opened).
- **A pet's shape comes from its project, its colour from its session**: every session of a project, and of its git worktrees (Claude desktop makes one per session), has the same creature, each session in its own colour. When a session of the project ends or starts, the others' colours change in the panel's list, its details and on the pets at once (they used to keep the old colour until something else changed). A project can get its own picture as the pet's face (PNG, JPG, GIF or WebP up to 2 MB, from the panel's Change pet; Default pet undoes it). Pictures stay in the app's data folder; GIFs stay animated.
- **Pet pictures as pixel art**: a picture chosen in **Change pet** opens a dialog that shows it as pixel art, on its own and on the pet. You choose whether it is the face in the project's creature (each session keeps its colour) or the whole pet, and set the size (32, 48 or 64 px), the number of colours and accent colours, stray-pixel clean-up, the outline (a darker shade of the picture's darkest colour, or a colour of your own: a swatch, the colour picker or a typed code such as `#f0a`, `rgb(255 0 128)` or `hsl(200 80% 40%)`) and background removal, and save when it looks right; **Edit picture** reopens it from the stored original. A GIF stays animated. A WebP picture is decoded in a hidden page (first frame only): Electron's `nativeImage` can't read WebP on Linux.
- **Show when needed** (#55, Settings → Pet mode): nothing on the edge; only a session that needs you (waiting, just done, context under 25%) shows, its pet hanging under the app's pixel balloon and rising from below the screen to past the top, in its own column away from the pointer and the other pets, again and again until the need is over (a finished task crosses once). Pointing at it stops it and opens its card (Allow / Deny while it waits); answering pops the balloon. A corner pill counts the sessions and lists them with Allow / Deny. **Do not disturb** 30 / 60 min (Settings) hides the pets in both modes and the notifications; the pill can end it. Reduced motion: the pet stands near the bottom edge. The overlay covers the whole work area in this mode (hidden while there is nothing to show). Not done: hiding while an app is full screen, and an "error" need (Bobix does not track session errors).
- **One line of pets** (replaces the family card and "+N" below): every pet, side sessions included, walks one way along the edge (Settings: left to right or right to left) at one speed, evenly spaced; it fades out at the far end of its stretch and comes in again at the near end, a family as one block behind its parent. More pets than fit take turns instead of folding into "+N". Each pet shows its own state with an effect kept to its own slot (a tight pulsing outline while it waits, the tool held in its hands, a compact XP bar, battery and goodbye), and no status balloon while effects run (balloons come back with reduced motion). Pointing at a pet stops the whole line and shows that pet's card or its request with Allow / Deny; a click opens that pet's session. Dragging a pet (with its family) takes it out of the line; let go and it slides into the line at the nearest free place. A real-Chrome test reads the composited overlay and fails on any effect pixel over another pet, tag or balloon, or two pets in sight overlapping.
- **Side sessions stand with their parent**: up to 10 side sessions stand right next to their parent pet in colours of their own (the rest as "+N"), on one name tag that is the ground the family stands on; dragging any of them moves the family. While at most two of them need you, each pet holds a pixel balloon (orange "!" waits for you, green tick is done; a press opens its card with Allow / Deny); from three, one bubble sums them up and opens the family card. The approval countdown no longer redraws (and flickers) the card every second.
- **Feedback** (a button at the top of the panel on every tab, and the tray menu): a bug or an idea opens GitHub's new-issue form, filled in, and the person submits it themselves. Errors of the main process are kept in memory for it, so a crash is not captured.
- **Quest and log in full**: the details keep the whole prompt (up to 32,000 characters; a longer one ends in "[…]" on its own line) and show it as Markdown, like the final report (tables, nested lists, code, quotes); Quest shows its first lines and each log line 2, with **Show more** where there is more. The session row, the log and the pet's card show the prompt without its Markdown signs.
- **Permission requests wait on the pet until you answer**: a new install holds a request in Bobix until it is answered there (or Esc in the terminal) instead of 60 s; a time limit can still be set, and stored settings keep their value. Nothing is held while pets are hidden or notifications are paused.
- **Clicks reach the app under the pets again**: a pet dragged while its session ended left the drag open, and the whole strip at the bottom of the screen kept the mouse (Claude's prompt box there could not be clicked) until Bobix restarted; letting go anywhere now ends the drag.
- **Family card and balloons, fixed after an audit**: the family card's Allow / Deny / Open buttons take clicks (they passed through to the app below) and the card opens above the summary bubble, which closes it again; the card sits above other pets; the "+N" balloon takes clicks and goes after 90 s like the side sessions' own; on the Top edge balloons hang below the name tag instead of off the screen; a pet that stops next to a family keeps clear of its side sessions and a pet on its own stays above a family it walks past; a family's name tag stops at the screen's ends; an unknown context shows an empty bar on the pet card; running Bobix from a clone no longer turns "start at login" off for the installed app.
- **Pets and previews**: when a click on a pet can't open its session, the panel opens on it with a hint (where it runs, and Alt+Tab on Wayland) instead of an error toast on every click; one-line previews, pet cards and notifications show the answer without Markdown marks.
- **How to read the pets, and What's new**: once the first pet appears, a new install's panel shows what each pet's look means, how to open a session and how to answer a permission request (also in Setup, always). Someone updating from an older Bobix instead sees a short "What's new in Bobix 0.1.4" card once, and a tray item for it until it is closed. The notes ship inside the app; nothing is fetched.
- **Work items** (first version): a session's details show its git status (branch, changed files, commits not pushed, ahead / behind its upstream, last commit, worktrees), read locally with `git` at most every 30 s. A new **Work** tab lists the open GitLab issues assigned to you, grouped by project (projects whose repository a session used here first, the rest under "Not seen on this machine"), with labels, due date, a link to the browser and the session working on it, and a Projects dropdown to show only the projects you pick (all by default; filtered in the app, no extra request): a branch named `<number>-…` (GitLab's branch from an issue) in a repository of that project links the session to the issue, and the session shows `#<number>`. Off by default; one switch in Settings, no URL to type: Bobix asks your own `glab` which GitLabs it is signed in to (`glab auth status`) and reads the issues of each (a host whose sign-in fails is left out). Bobix keeps no token; if glab is missing or signed in nowhere, the tab says to run `glab auth login` yourself. Read-only. Checked on macOS against a self-hosted GitLab (21 issues, same as `glab api`); Windows, Linux and gitlab.com not yet.
- **Panel as a status board**: the panel is a board with one column per state (To do, Waiting for you, Working, Just done, Resting), cards instead of rows, and a session's details in a drawer from the right. To do holds the GitLab issues no session in the list works on (with New or Resume, the Projects picker and Refresh), so the Work tab is gone; an issue with a session shows as that session's `#<number>`, and Open session in its details resumes it. A waiting request can be answered on its card. Below 900 px one column shows at a time, picked from a row of chips. Warmer colours, and a dark look that follows the system. Checked from source on macOS with pretend sessions (light, dark, 1180 and 420 px); not yet with real sessions or on Windows / Linux.
- **Start work from an issue**: each issue of a project on this machine has one button on its card in the To do column. **Resume** opens the session working on it: one in Bobix's list (same as a click on its pet), else the newest Claude desktop session in the project's folder named `[<CODE>-<number>]…` (or `<project> #<number>…`, the first format) (read from Claude desktop's own session list, so it works after Bobix restarts; archived ones are left out). **New** opens a new Claude desktop session in the project's own folder with Claude's documented `claude://code/new?folder=…` link (no prompt sent) and the issue shows "Waiting for a new session ✕ Cancel": the first session *created* in exactly that folder afterwards takes the issue, whatever other sessions are open there (open, resumed, cleared or forked sessions never count as created), and is named `[<CODE>-<number>] <short title>`, e.g. `[BAK-23] Fix the login`, through Bobix's SessionStart hook (`sessionTitle`, the same as `/rename`). A project's code is made from its name (first two letters of the first word and the first letter of the last: `ba-qa-kit` → `BAK`, one word: its first three letters) and can be set per project in Settings → Project codes. No question, nothing guessed from timing, nothing stored by Bobix besides the codes you set. A session also works on an issue when a branch it was on names it (`<number>-…`); a side session takes its parent's issue.

Everything before that is in v0.1.3 (2026-11-04), see its [release notes](https://github.com/baonguyen-agilityio/bobix/releases/tag/v0.1.3).


Release checklist: bump `version` in `package.json` → tag `vX.Y.Z` → check the 5 fixed-name files are attached → add release notes.

## 3. Planned features

Small, they reuse data Bobix already has. Good to do together:

- [x] **Pick the next issue** ([#54](https://github.com/baonguyen-agilityio/bobix/issues/54)): To do suggests the issue to start next (on this machine, nobody started it: due soonest, then the oldest). Start opens a box with the prompt Claude gets (title, description read now, link), editable; then Bobix copies it and opens a new Claude desktop session in the folder with `claude://code/new?folder=…&q=…` (the prompt box filled in, documented by Claude). The session is linked to the issue as before. Checked from source with pretend sessions; that the Claude app fills the box with `q` is from its help page, not tried here.
- [x] **A skill per ticket** ([#76](https://github.com/baonguyen-agilityio/bobix/issues/76)): the Start box lists the skills Claude Code has for that folder (yours, the repo's `.claude/skills`, enabled plugins, your organization's, your claude.ai account's), names and descriptions only, read-only, as a choice: the one Bobix suggests from the issue's labels and your role (Settings → Your role: BA, QA, Dev) comes first, preselected and marked Suggested with its reason; three show until "See all N skills", and "No skill" is always there. The prompt starts with `/<skill> <issue link>` and stays editable; nothing starts without your click. Two groups: **Project process** (the repository's skills, the team's plugins, your organization's) first, then **Yours** (only the skills you pin in Settings → My skills, each for the roles you choose), and a search over every skill. A team can write its process in `.bobix/skills.json` ([format](skill-process.md)): which skill for which label, step or role. It replaces the label / role guess for that repository, or anyone can import one from a file or an https link in Settings → Skill process. A skill it names that Claude lacks shows as not installed, with a line to copy for Claude. Where skills live: from Claude Code's docs, and checked on disk on macOS only (Windows and Linux paths are the documented ones, not tried). Whether Claude runs a `/skill` prompt that `claude://code/new?q=` filled in is not tried; the prompt is copied too.
- [x] **Costumes by state** ([#91](https://github.com/baonguyen-agilityio/bobix/issues/91), on `develop`, not released): each pet wears its state, drawn into its own 36×36 pixels so the effects draw the same dressed pet: a hard hat while working (a headlamp while reading or searching) with the tool in its hand, moving (a pencil writing, a little terminal typing, a magnifier sweeping, a turning globe) in place of the effect's tool card; a signal lamp while it waits; a crown and a waving checked flag when done, put on after the XP (and after the low-context battery, which crossed them otherwise); heavy eyelids on low context; a nightcap asleep. Props are held on the side the pet walks to; no costume pixel leaves the pet's box (tested against every effect, both edges, both directions, all frames, and on the real overlay in Chrome). No setting. Not done: picture pets keep their picture undressed, "Show when needed" pets are not dressed, and the bandage drawn for an error has no session state to show it (Bobix does not track errors). Checked on macOS from a debug build; Windows and Linux by CI only.
- [ ] **Remind when stuck**: a session waiting for approval longer than N minutes notifies again, and its pet changes look.
- [ ] **Global shortcut**: jump to the next session that is waiting for you.
- [ ] **Cost per session**: tokens used (from the transcript), and a total for the day.
- [ ] **Stop / resume**: stop a running session (interrupt its claude process); copy `claude --resume <id>` for a session whose terminal is closed.

## 4. Known limits (by design or outside Bobix's control)

- Builds are not code-signed: macOS and Windows warn on first launch.
- Linux Wayland: no app may bring another app's window forward, so a click on a terminal session's pet opens it in the panel and names the terminal instead. Sessions in the Claude desktop app open directly.
- Linux Wayland: through XWayland, Bobix sees the cursor only while it is on a pet, so fading near the cursor works only right next to a pet.
- Linux Wayland: no app may bring another app's window forward, so a click on a terminal session's pet opens it in the panel and names the terminal instead. Sessions in the Claude desktop app open directly, and a CLI in the Claude app's own terminal brings the app forward (not its terminal tab).
- Opening a session in the Claude desktop app uses `claude://code/continue`, not a documented API; it may change.
- While Bobix holds a permission request, Claude Code shows its own permission prompt in the terminal at the same time (checked with Claude Code 2.1.318), so an answer in either place goes through and a stuck Bobix never blocks Claude. Not checked: the Claude desktop app's own prompt, and older Claude Code versions.
- Approvals need the Node.js forwarder; with the curl / PowerShell fallback Bobix only watches.
- Linux installers are `.deb` only (Ubuntu, Debian). Other distributions aren't packaged.
- Only Claude Code sessions (terminal, IDE, the Code tab of the Claude app). Ordinary chats in the Claude app or on claude.ai have no hooks, so Bobix can't follow them.
  - Checked on 2026-11-04 on macOS while a chat answered: Claude desktop's logs (`~/Library/Logs/Claude`) record nothing about chats, and the only chat-related writes are to claude.ai's internal IndexedDB, which keep happening after the answer ends, so they can't serve as a status. Reading that database would mean reading private chat data in an undocumented format.
  - Not tried, decided against for now: reading the app's UI through the Accessibility API (e.g. whether a "Stop" button is showing; needs the Accessibility permission and breaks when the UI changes), and a browser extension for claude.ai on the web (does not cover the desktop app).
- To do column, issues and sessions:
  - A project gets New / Resume only once a session Bobix saw since it started used its repository; after Bobix restarts, a project is under "Not seen on this machine" until one of its sessions does something.
  - After New, if you don't create the session, the next session you create in that folder later takes the issue. Cancel it with ✕ on the issue's card. The wait is kept in memory only: a Bobix restart drops it.
  - Resume after a restart finds the session by its name in Claude desktop's session files (not a documented format). A session you rename yourself, or one named with a project code you changed since, is not found; the button says New again. Several sessions of one issue: Resume opens the one used last.
  - Several main sessions in one project folder share its files and can edit the same ones; Bobix doesn't prevent it. Side sessions Claude starts get their own worktree.
  - Only the first 100 open issues per GitLab are read. The same project path on two GitLabs counts as one project.
- Memory is about 330–400 MB (Electron).
